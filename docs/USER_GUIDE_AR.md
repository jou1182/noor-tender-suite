# دليل استخدام منصة Noor AI
### منصة الذكاء المتعدد الوكلاء لذكاء المنافسات الإنشائية — Multi-Agent Tender Intelligence

> آخر تحديث: 2026-08-25 — يغطي هذا الدليل دورة الحياة الكاملة بعد تحديثات «القوائم الديناميكية وإطلاق السرب وغرفة تدريب الوكلاء».

---

## 1. تشغيل المنصة

### الطريقة السهلة (الموصى بها) ⭐
على سطح المكتب ستجد: **`Noor.bat`** — نقرة واحدة فقط:
1. يشغّل Docker Desktop إن لم يكن يعمل
2. يشغّل حاويات المنصة
3. ينتظر حتى تجهز فعلاً
4. **يفتح المتصفح على العنوان الصحيح تلقائياً**

> لن تحتاج لكتابة أي عنوان أو أمر بعد اليوم — انقر النقرة وانتظر المتصفح.

### ما معنى منفذَين؟ (توضيح)
| المنفذ | هو ماذا | هل تكتبه في المتصفح؟ |
|---|---|---|
| **3000** | صالة المطعم — الواجهة التي تتعامل معها | ✅ نعم، هذا فقط |
| **8000** | المطبخ — محرك الذكاء الذي تناديه الواجهة تلقائياً | ❌ لا، أبداً |

الواجهة تتخاطب مع المحرك خلف الكواليس عند كل ضغطة زر. كلا المنفذين يجب أن يعملا، لكنك تزور **3000 فقط**.

### الطريقة اليدوية (للمطوّرين)

| المكوّن | الأمر | العنوان |
|---|---|---|
| الخادم الخلفي (FastAPI) | `.venv/Scripts/python.exe -m uvicorn app.main:app --port 8000` | http://localhost:8000 |
| الواجهة الأمامية (Next.js) | `cd frontend && npm run dev` | http://localhost:3000 |
| عبر Docker | `docker compose up -d` | http://localhost:3000 |
| اختبارات الجودة | `.venv/Scripts/python.exe -m pytest tests/ -q` | 176 اختباراً |

> ⚠️ **مهم:** بيئة التشغيل الفعلية هي Docker. أي تعديل جديد على الكود يتطلب إعادة البناء:
> `docker compose build backend frontend && docker compose up -d`

عند إقلاع الخادم تُنشأ الجداول وتُزرع بيانات الوكلاء الافتراضية تلقائياً (`Platform seed`).

## 2. رحلة المستخدم — من الملف إلى العرض المختوم

### الخطوة 1 — إنشاء مساحة عمل (منافسة)
- من القائمة العلوية اضغط على **مبدّل مساحات العمل** (اسم المنافسة الحالي).
- القائمة تعرض **المنافسات الحقيقية من قاعدة البيانات** — لا عملاء ثابتين في النظام.
- في أسفل القائمة: اكتب اسم المنافسة + الجهة المالكة ثم اضغط **New**.
- كل عنصر في القائمة يظهر حالته (Draft / Swarm Running / Completed) وعدد مستنداته والنتيجة الفنية إن جُرّبت.

### الخطوة 2 — رفع حزمة المنافسة (RFP)
- اضغط زر **Upload Tender Package** الأزرق في الأعلى.
- اسحب الملفات أو تصفح: `PDF / XLSX / XLS / XER / IFC`.
  - ملفات RFP: كراسة الشروط، معايير التقييم، المواصفات…
  - ملف جدول زمني واحد بصيغة XER (إجباري لإطلاق السرب).
- أثناء الرفع ترى مراحل التقدم، وبعد النجاح:
  - تُسجل المنافسة تلقائياً في القائمة العلوية.
  - يُفتح بث حي لتتبع سرب الوكلاء.

> ⚠️ لا يمكن إطلاق السرب إلا بعد وجود **RFP واحد على الأقل + ملف XER**.

### الخطوة 3 — الانطلاق بالوكلاء 🚀
هذا هو الزر الذي كان مفقوداً: بعد الرفع (أو في أي وقت لاحق) اضغط زر
**«انطلق أيها الوكلاء»** في قسم *Multi-Agent Swarm Orchestration*.
- يشعل السرب العشري (10 وكلاء متسلسلين) على المنافسة الحالية.
- الحالة تتغير إلى **Swarm Running…** ولا يمكن الإطلاق المزدوج.
- شاهد اللوحة الحية: كل عقدة وكيل تتلون (IDLE → RUNNING → COMPLETED) مع التلمترية والزمن والنموذج المستخدم.
- عند الاكتمال تظهر النتيجة الفنية `/100` وتتغذى عليها استوديوهات العمل أدناه.

### الخطوة 4 — استكشاف النتائج (استوديوهات العمل)
11 استوديو تحت لوحة واحدة: الامتثال لـRFP، مراجعة Submittal، هندسة القيمة، صحة الجدول الزمني (DCMA + مونتي كارلو)، محاكاة 4D، ITP/HSE، المطالبات وEoT، الدفعات IPC، عمليات الموقع، التصدير الرئيسي، وسجل البلوكتشين.

### الخطوة 5 — الرجوع للخلف والمسح الآمن
**حذف مستند واحد:** مكتبة الوثائق → أيقونة سلة بجانب كل مستند → تأكيد ✓.
يُمسح نهائياً: السجل + الشرائح النصية + متجهات Qdrant + الملف من القرص.

**حذف منافسة كاملة:** القائمة العلوية → أيقونة السلة بجانب المنافسة → تأكيد ✓.
يُمسح نهائياً وبالترتيب الآمن: سجلات الامتثال ← المستندات ← سجل التدقيق ← الملفات من القرص ← المنافسة نفسها.
إن كانت هي المساحة النشطة تنتقل تلقائياً لأول منافسة متبقية.

## 3. غرفة تدريب الوكلاء (Settings → Agent Registry & Training)

كل شيء في بطاقة الوكيل قابل للتعديل — **لا شيء صلب**:

| العنصر | كيف تعدّله |
|---|---|
| الاسم العربي | حقل نصي مباشر (مثال: عارف) |
| الاسم الإنجليزي | حقل نصي مباشر أيضاً — أصبح قابلاً للتعديل مثل العربي |
| الصورة (Emoji) | اضغط الدائرة واكتب الإيموجي الجديد |
| الدور | حقل نصي تحت الاسم |
| برومبت التدريب | زر **التدريب ✨** → محرر System Prompt كامل |
| المزود والنموذج | قائمة المزودين + خانة Model Override + منزلق الحرارة |

- التعديلات تظهر بإطار أخضر (غير محفوظة). اضغط **حفظ التعديلات** أو **تراجع**.
- زر **تجربة ▶**: معاينة حية قبل الحفظ! اكتب رسالة + سياق اختياري من مستندات المنافسة وشاهد ردّ الوكيل بهويته الجديدة — دون تخزين أي شيء.
- مفاتيح الوكلاء (`#key`) ثابتة لأن السرب يستدعيهم بها؛ ما تغيّر هو الهوية الظاهرة والسلوك.

### مزودو LLM (نفس الشاشة → LLM Providers)
أضف OpenAI/Claude/Gemini/DeepSeek أو مزوداً محلياً خاصاً (Ollama/LM Studio)، فعّله، واختبر الاتصال بزر **Test**. زر التجربة للوكلاء يحتاج مزوداً واحداً مفعلاً على الأقل.

## 4. مكتبة الوثائق والسؤال في المنافسة
- ارفع مستندات إضافية (DOCX/DXF/DWG/ZIP…) أو امسح مجلداً كاملاً من الخادم.
- صنّف تلقائياً أو ثبّت **وثيقة معايير التقييم** (Pin) ليستخرجها النظام كبوابات إلزامية وأوزان.
- اسأل المنافسة بلغتك: *«أين شرط الخرسانة المسلحة؟»* — الإجابة تستشهد بالملف ورقم الصفحة.

---

## 4.ب. مركز القيادة الحية والاستوديوهات — كل شيء من بياناتك

**لا أرقام وهمية بعد اليوم:**
- **Tender Portfolio — Live**: عدد المنافسات الحقيقية، متوسط الدرجات الفنية الفعلية، المستندات المبتلعة، توزيع أحكام الامتثال من سجلاتك.
- **System Telemetry**: الوكلاء المفعّلون، عدد مرات تشغيل السرب، المزودون المتاحون، وآخر أنشطة التدقيق الحقيقية بتوقيتها.
- **RFP Compliance Studio**: يعرض الآن سجلات الامتثال **للمنافسة النشطة فقط** من قاعدة البيانات، مع عنوان المنافسة بجانب الاسم — وقبل أول تدقيق سترى رسالة دعوة للإطلاق بدل بيانات مزيفة.
- **بطاقة LLM Gateway** لا تظهر إلا بعد تشغيل سرب فعلي ينتج قياسات حقيقية.

> القاعدة العامة: أي بطاقة لا تملك بيانات حقيقية لها تعرض حالة فراغ صريحة بدل أرقام مختلقة.

## 5. الأسئلة الشائعة

**القائمة العلوية كانت تعرض أرامكو و… لماذا؟**
كانت ثابتة في الكود لأغراض العرض. الآن مصدرها الوحيد قاعدة البيانات، وأنشئ/احذف حرّة.

**رفعت الملفات… وماذا بعد؟**
اضغط «انطلق أيها الوكلاء». الرفع وحده لا يشغل شيئاً — وهذا مقصود كي تتحكم بتوقيت الإطلاق.

**حذفت منافسة بالخطأ — هل يمكن استرجاعها؟**
الحذف نهائي (ملفات + قاعدة بيانات) لهذا يطلب تأكيداً صريحاً. استخدم نسخ النسخ الاحتياطي (`scripts/backup_restore_manager.py`) للمهم.

**التجربة فشلت برسالة «لا يوجد مزوّد»؟**
فعّل مزوداً واحداً من تبويب LLM Providers أولاً، ثم أعد التجربة.
